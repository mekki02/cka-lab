Passwords, API tokens and TLS keys need the same treatment as configuration — outside the image — plus a little more care. Kubernetes stores them in **Secrets**, which look almost exactly like ConfigMaps. The most important thing to understand is what a Secret does **not** do: base64 is an encoding, not encryption. The protection comes from access control, and from how you consume the Secret.

<Phase step="theory" />

## Secrets vs ConfigMaps

| | ConfigMap | Secret |
|---|---|---|
| Values in the manifest | plain text in `data` | **base64** in `data`, or plain text in `stringData` (converted on write) |
| Typical content | settings, config files | passwords, tokens, keys, certificates |
| Consumed as | env, envFrom, volume | env, envFrom, volume — same syntax with `secretKeyRef` / `secretRef` / `secret` |
| Volume files | normal files | files on a **tmpfs** (memory), never written to the node's disk |
| Extra protections | — | separate RBAC (you can grant ConfigMaps but not Secrets), optional encryption at rest in etcd, `immutable: true` |

## Secret types

| Type | Created with | Keys |
|---|---|---|
| `Opaque` (default) | `k create secret generic` | anything you choose |
| `kubernetes.io/tls` | `k create secret tls --cert --key` | `tls.crt`, `tls.key` |
| `kubernetes.io/dockerconfigjson` | `k create secret docker-registry` | `.dockerconfigjson` — used as an `imagePullSecret` |
| `kubernetes.io/service-account-token` | (legacy, avoid) | `token`, `ca.crt` |
| `kubernetes.io/basic-auth` | YAML | `username`, `password` |

## base64 is not encryption

```bash
echo -n 's3cr3t' | base64          # czNjcjN0
echo 'czNjcjN0' | base64 -d        # s3cr3t
```

Anyone who can `get` the Secret can decode it in one command. What really protects a Secret:

- **RBAC**: give applications and people `get` on Secrets only where needed;
- **encryption at rest** in etcd (an administrator setting — CKA territory);
- **consuming it as files** rather than environment variables: env values leak into crash dumps, `/proc/<pid>/environ` and child processes, and are easy to print by accident.

<Callout type="warning">
`echo 'pass' | base64` includes the trailing newline in the encoded value. Use `echo -n` (or `printf %s`) when you encode by hand — or let kubectl do it with `--from-literal`, or write plain values under `stringData`.
</Callout>

## Create Secrets

```bash
k create secret generic db-cred --from-literal=username=shop --from-literal=password='p@ss w0rd'
k create secret generic api-key --from-file=key=./api.key
k create secret tls shop-tls --cert=tls.crt --key=tls.key
k create secret docker-registry regcred --docker-server=registry.example.com \
  --docker-username=ci --docker-password='…'
```

In YAML, prefer `stringData` for readability — the API server base64-encodes it into `data`:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-cred
type: Opaque
stringData:
  username: shop
  password: p@ss w0rd
```

## Read Secrets (when you are allowed to)

```bash
k get secret db-cred -o yaml                                   # values in base64
k get secret db-cred -o jsonpath='{.data.password}' | base64 -d; echo
k describe secret db-cred                                      # sizes only, no values
```

## Consume Secrets

```yaml
spec:
  containers:
  - name: app
    image: busybox:1.36
    command: ["sh", "-c", "echo user=$DB_USER; ls -l /etc/db; sleep 3600"]
    env:
    - name: DB_USER
      valueFrom:
        secretKeyRef:
          name: db-cred
          key: username
    volumeMounts:
    - name: db
      mountPath: /etc/db
      readOnly: true
  volumes:
  - name: db
    secret:
      secretName: db-cred          # note: secretName, not name
      defaultMode: 0400            # files readable by the owner only
```

All keys as variables: `envFrom: [{ secretRef: { name: db-cred } }]`. Pull from a private registry: `spec.imagePullSecrets: [{ name: regcred }]`.

<Terminal
  command="k exec app -- ls -l /etc/db"
  output={`total 0
lrwxrwxrwx    1 root     root            15 Nov 26 10:12 password -> ..data/password
lrwxrwxrwx    1 root     root            15 Nov 26 10:12 username -> ..data/username`}
/>

The symlinks to `..data` are how the kubelet swaps all files at once when the Secret changes.

<Callout type="exam" title="Exam tip">
The volume field is `secret.secretName`; for a ConfigMap it is `configMap.name`. Mixing them up is the most common typo in Secret tasks — `k explain pod.spec.volumes.secret` settles it.
</Callout>

## Practical example: immutable Secrets

```bash
k create secret generic release-key --from-literal=key=v1 $do | yq '.immutable = true' | k apply -f -
k create secret generic release-key --from-literal=key=v2 $do | k apply -f -
# The Secret "release-key" is invalid: data: Forbidden: field is immutable when `immutable` is set
```

Immutable Secrets (and ConfigMaps) protect against accidental changes and spare the API server from watching them. To change one, create a new Secret with a new name and point the Deployment at it.

## Guided exercise

<Exercise kind="guided" title="Credentials as files">

1. Create `db-cred` with `username=shop` and `password=p@ss w0rd`.
2. Apply the `app` Pod above.
3. Print the password from inside the container, then from the API with jsonpath + base64.

<Solution>

```bash
k exec app -- cat /etc/db/password; echo
k get secret db-cred -o jsonpath='{.data.password}' | base64 -d; echo
```

Both print `p@ss w0rd`. The quotes in `--from-literal=password='p@ss w0rd'` protect the space from your shell.

</Solution>

## Independent challenge

<Exercise kind="challenge" title="From a .env file">

You receive `prod.env`:

```text
STRIPE_KEY=sk_live_123
SMTP_PASSWORD=mail-secret
```

Create a Secret `prod-env` with one key per line, and a Pod `billing` (`busybox:1.36`, `sleep 3600`) that receives **all** of them as environment variables prefixed with `APP_`.

<Solution>

```bash
k create secret generic prod-env --from-env-file=prod.env
```

```yaml
spec:
  containers:
  - name: billing
    image: busybox:1.36
    command: ["sleep", "3600"]
    envFrom:
    - secretRef:
        name: prod-env
      prefix: APP_
```

`k exec billing -- printenv APP_STRIPE_KEY` prints `sk_live_123`.

</Solution>
</Exercise>

## Troubleshooting

<Exercise kind="troubleshooting" title="The password is wrong — by one character">

An application rejects the database password from Secret `db`. `k get secret db -o jsonpath='{.data.password}'` shows `c2VjcmV0Cg==`. What is wrong?

<Solution>

`c2VjcmV0Cg==` decodes to `secret` followed by a **newline** (`Cg==` is `\n`): someone encoded it with `echo` instead of `echo -n`. Recreate it without the newline: `k create secret generic db --from-literal=password=secret $do | k apply -f -` (or use `stringData`), then restart the Pods if they read it from the environment.

</Solution>
</Exercise>

<Callout type="mistakes">

- Thinking base64 protects anything.
- Encoding with `echo` (trailing newline) instead of `echo -n`.
- `secret.name` instead of `secret.secretName` in a volume.
- Putting secrets into ConfigMaps, or printing them in logs.

</Callout>
